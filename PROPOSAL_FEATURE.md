# Proposal ("مقترح") Feature — Implementation Notes

Documents the "Proposal" feature added to the Load Alerts report so it can be ported into
another project. Two files are involved:

- `index.html` — hosts the alerts report, the entry-point button, and the overlay window
  that displays the proposal form in an iframe.
- `مقترح.html` — the standalone proposal form itself (can also be opened directly as a file).

---

## 1. Entry point (inside the Load Alerts report)

In the alerts report (generated by `openAlerts()` in `index.html`), each overloaded
transformer/cable row has a small **📤 (Share)** icon button. A second **📝 (Proposal)**
icon button sits right next to it (same size, same style — small square icon buttons, no
text label), in all 4 render targets: `txBody`, `cbBody`, `txCards`, `cbCards`.

```js
function proposalOne(idx, type){
  var a=(type==='tx'?txf:cbf)[idx];
  if(!a) return;
  parent.openProposal(a.uid, type, type==='cb'?a.feederNum:null);
}
```

This calls a function defined in the **parent** page (`index.html`), not inside the
alerts report iframe, because the parent has access to the app's real data (`records`,
`loadings`, `getAllRounds`).

`CB` (cable/feeder alerts) rows also carry `feederNum` (the raw feeder number, not just
the formatted "F3" string) so the specific overloaded feeder can be looked up later.

## 2. `openProposal(uid, type, feederNum)` — building the payload (in `index.html`)

- Looks up the transformer record (`records.find(r => r.uid === uid)`).
- Pulls **all reading rounds** via `getAllRounds(uid)` (not just the latest).
- For each round, computes:
  - Voltage readings (`vRN, vYN, vBN, vRY, vRB, vYB`) from `round.volt` (`vL1N`, `vL2N`, `vL3N`, `vL1L2`, `vL1L3`, `vL2L3`).
  - Transformer load per phase (`tR, tY, tB, tN`) = sum of all feeders' currents in that round.
  - Feeder load per phase (`fR, fY, fB, fN`) + `fNum` (the feeder number those currents
    belong to), `fSize` (its cable size in mm²) and `fAmp` (that cable's ampacity) — see
    §2.1 for how the feeder is picked and §2.2 for how its % is computed.
  - A human label per round, e.g. `"Round 2 — 12/05 14:30"`.
- Payload shape:
  ```js
  { station, txNo, cap, lat, lng, type, bestRound,
    rounds: [ {label, vRN..vYB, tR..tN, fR..fN, fNum, fSize, fAmp}, ... ] }
  ```

## 2.1 Which feeder fills the "Feeder Load" table (and which round opens first)

There are two kinds of overload alert — **transformer** (`type==='tx'`) and **feeder/cable**
(`type==='cb'`) — and the Feeder Load half of the current table must always describe the
feeder that is actually carrying the load, e.g. TX 125 → feeder 5.

**Feeder pick, per round** (in `openProposal`, `index.html`):
```js
let tgt = null;
if (feederNum != null && feederNum !== '') tgt = fds.find(x => String(x.num) === String(feederNum)) || null;
if (!tgt && fds.length) {
  // fallback: the feeder with the highest phase current in this round
  tgt = fds.reduce((best, f) => {
    const cur  = Math.max(parseFloat(f.iL1)||0, parseFloat(f.iL2)||0, parseFloat(f.iL3)||0);
    const bcur = best ? Math.max(parseFloat(best.iL1)||0, parseFloat(best.iL2)||0, parseFloat(best.iL3)||0) : -1;
    return cur > bcur ? f : best;
  }, null);
}
```
So:
- **Feeder alert** — the alert row's own `feederNum` wins. If that feeder has no reading in
  a given round (it can be missing from an older round), that round falls back to the
  most-loaded feeder instead of leaving the table blank.
- **Transformer alert** — no `feederNum` is passed, so the fallback always applies: the
  proposal shows the transformer's most-loaded feeder. Previously the whole Feeder Load
  half stayed empty for `tx` alerts.

`fNum` (the chosen feeder's number) travels with each round and is rendered in the form
header as `Feeder Load (F5)` — both in the current table's group header and in the
`Feeder Load … %` row — so it's never ambiguous which feeder the numbers came from. It
re-computes on every round switch, since the most-loaded feeder can differ per round.

## 2.2 The two percentages are computed on different bases

- **TX. Load %** — against the transformer's rated current:
  `rated = cap·1000 / (√3 · 415)`, `txPct = max(tR,tY,tB) / rated`.
- **Feeder Load %** — against the **cable's ampacity**, *not* the transformer rating. This
  matches `cableStatus()` in `index.html`, which is what raises the cable alert in the first
  place, so the number in the proposal now agrees with the number in the alerts list.
  Previously `fPct` reused `_pct(d.cap, …)` and reported a transformer-percentage under a
  "Feeder Load" label — that was the wrong basis.

`openProposal` resolves the ampacity from the chosen feeder's cable size
(`CABLE_AMPACITY[parseInt(tgt.name)]`) and ships it per round as `fAmp` (with `fSize` for
display). `مقترح.html` then uses a separate helper:
```js
function _pctCable(amp, cur) {
  const a = Number(amp) || 0;
  if (!a || !cur) return '';
  return String(Math.round((Number(cur) / a) * 100));
}
d.fPct = _pctCable(d.fAmp, Math.max(Number(d.fR)||0, Number(d.fY)||0, Number(d.fB)||0));
```
If the cable size is unknown/unmapped there's no ampacity, so `fPct` renders blank rather
than a misleading figure — the cell stays `contenteditable` for a manual entry. The group
header shows only the feeder number — `Feeder Load (F4)`; the cable size is deliberately
*not* repeated there, since it already has its own "Main cable/conductor size" row below.

**Main cable/conductor size** is auto-filled from the same feeder, in `renderRound`:
```js
if (d.fSize && !d.cableSize) d.cableSize = d.fSize + ' mm²';
```
The `!d.cableSize` guard means it only fills an *empty* field, so anything the user typed
(synced into `d` by the `focusout` listener, §4) survives a round switch or re-render. It
also loses to a saved value: `_loadSavedProposal` maps `cable_size: r.cable_size ||
d.cableSize`, so a stored size wins and the auto-fill stays as the fallback when the DB
value is empty.

**Default round** — the form used to always open on Round 1, which could show a near-empty
reading while the overload sat in a later round. `openProposal` now computes `bestRound`:
the index of the round with the highest **feeder** current for `cb` alerts, or the highest
**transformer** current for `tx` alerts. `مقترح.html` opens on `_payload.bestRound` and
highlights that round's button; the user can still click any other round.
- Payload is written to `sessionStorage.setItem('proposalData', JSON.stringify(payload))`
  — this is how data crosses into the iframe (see §3), since the iframe navigates to a
  real file URL (`مقترح.html`), not `srcdoc`, so it can't receive data via closures.
- An overlay (`#proposalOverlay`, top `z-index:10000`, stacks above the alerts overlay) is
  created/reused with a header bar (Back button, title, and now also Print/Export
  Word/Save buttons — see §5) and an `<iframe id="proposalFrame">`.
- The iframe `src` is set to `encodeURI('مقترح.html') + '?t=' + Date.now()` — the
  timestamp query param forces a fresh navigation/reload every time (so a changed
  `sessionStorage` payload is actually picked up, and `_loadSavedProposal()` re-runs).
- `closeProposalOverlay()` just hides the overlay div.

## 3. `مقترح.html` — reading the payload

```js
let _payload = null;
try {
  const raw = sessionStorage.getItem('proposalData');
  if (raw) _payload = JSON.parse(raw);
} catch (e) {}
```

Also supports being opened **standalone** (double-clicked, no parent app) via URL query
params as a fallback: `?station=...&txNo=...&cap=...&txPct=...&fPct=...`.

If `_payload.rounds.length > 1`, a row of buttons is rendered above the form
(`#roundSelWrap`) — one per round — clicking one re-renders the whole form with that
round's readings via `renderRound(i)`. The currently selected button is highlighted blue.

`d.station/txNo/cap/lat/lng` come from the payload root; per-round fields come from
`_payload.rounds[i]`; `txPct`/`fPct` are computed client-side from the load values and
capacity:
```js
function _pct(cap, cur) {
  const rated = cap ? (Number(cap) * 1000) / (Math.sqrt(3) * 415) : 0; // 3-phase 415V
  if (!rated || !cur) return '';
  return String(Math.round((Number(cur) / rated) * 100));
}
```

## 4. Form layout — two real A4 pages

The whole form is built by `reportFormHtml(d)`, returning two sibling containers:

```html
<div class="a4-page"> ... page 1 ... </div>
<div class="a4-page page-break"> ... page 2 ... </div>
```

CSS:
```css
.a4-page { width:210mm; min-height:297mm; margin:0 auto 22px; background:#fff;
           padding:14mm; box-sizing:border-box; box-shadow:0 2px 14px rgba(0,0,0,.18); }
@media print {
  @page { size:A4; margin:0; }
  .a4-page { width:auto; min-height:auto; margin:0; padding:14mm; box-shadow:none; break-after:page; }
  .toolbar, .tip { display:none!important; }
}
```
On screen this renders as two distinct "paper sheets" on a grey background; when
printed, each `.a4-page` becomes its own physical A4 page.

**Page 1** — nama logo + "ENHANCEMENT PRE-INVESTMENT PROJECT APPRAISAL" header, then:
- PROJECT DETAILS (Ref No, Project Description, Area, District, Requesting Department).
  **District** (`Dhahira`) and **Requesting Department** (`Operation`) are pre-filled with
  defaults in the `d` object — they're the same on every proposal, so they're not retyped
  each time; both stay `contenteditable` for the exceptions. `_loadSavedProposal` restores
  them as `r.district || d.district` / `r.requesting_department || d.reqDept`, so a saved
  value wins and the default fills in when the stored value is empty.
- TRANSFORMER DETAILS (TX No, Capacity, No. of Complaints)
- Voltage Reading table (R-N, Y-N, B-N, R-Y, R-B, Y-B)
- TX Load / Feeder Load current table (R, Y, B, N each) + computed % badges. The Feeder
  Load side is titled with the feeder it describes — `Feeder Load (F5)` — see §2.1.
- Main cable/conductor size + Connection point (compact 2-column custom row: wide label,
  narrow input)
- PROJECT DESCRIPTION OPTION (Option 1/2 + Cost estimated)
- PROJECT REASON / RISK OF NOT EXECUTING PROPOSAL (free-text boxes)

**Page 2** — same nama header, then:
- NETWORK OVERVIEW (GIS) — **not** a live map; a fixed-size (100% × 260px) upload box.
  Clicking anywhere in the box (it's a `<label>` wrapping a hidden `<input type=file>`)
  opens the file picker; the chosen image is shown via `object-fit:cover` so the box
  never changes size regardless of the image's own dimensions. A small red ✕ button
  (top-right corner, `stopPropagation`+`preventDefault` so it doesn't also trigger the
  file picker) clears the image.
- Free Spare Available for New Proposed FD — Yes/No radio.
- List of additional required Asset — **checkboxes** (not radio: multi-select, and
  clicking a checked one again un-checks it — this is *why* checkboxes were chosen over
  radio) for Transformer/RMU/HFU/OLU/FP/MFP/SMFP/Cable, each with an editable Unit
  cell. The Transformer row's unit auto-fills with `capacity + 'KVA'`.
- RECOMMENDATIONS — a `<select>` dropdown (not free text) with a "Select.." placeholder
  and two canned recommendation sentences (`RECS` array) referencing Option 1 / Option 2.
- AUTHORIZATION APPROVAL table — Position / Name / Signature / Date rows for Operation
  Engineer, Operation Section Head, Operation Manager.
  - **Signature** cells: same fixed-size upload-box pattern as the GIS image, but on
    upload the image is run through a canvas pass that makes near-white pixels
    transparent (a crude "remove white background" filter) so a photographed paper
    signature looks like a clean overlay:
    ```js
    for (let i = 0; i < px.length; i += 4) {
      const brightness = (px[i]+px[i+1]+px[i+2]) / 3;
      if (brightness > 235) px[i+3] = 0;
      else if (brightness > 190) px[i+3] = Math.round(255 * (235 - brightness) / 45);
    }
    ```
  - **Date** cells use a real `<input type="date">` (native date picker) instead of a
    contenteditable cell.

Every value cell (`val`/`cval` helpers) is `contenteditable`, click-to-copy
(`_copyCell`), and — important for save/export — carries a `data-key="<d field>"`
attribute. A single delegated `focusout` listener on `#proposalForm` syncs whatever the
user typed back into the in-memory `d` object:
```js
document.getElementById('proposalForm').addEventListener('focusout', e => {
  const el = e.target.closest('[data-key]');
  if (el && el.isContentEditable) d[el.dataset.key] = el.textContent.trim();
});
```
(Radios/checkboxes/selects/date inputs write straight into `d` on their own
`onclick`/`onchange`.) This matters because `reportFormHtml(d)` re-renders the *entire*
form from scratch on every round switch / image upload — without the sync, typed text
would be silently discarded on re-render.

## 5. Toolbar (Print / Export Word / Save)

These three buttons live in the **parent overlay's header bar** (`index.html`,
`openProposal()`), next to the "↩ Back" button — not inside the iframe page itself.

**Cross-origin gotcha:** because the iframe's `src` is a real separate file
(`مقترح.html`), opening the app via `file://` makes the browser treat it as a different
origin from `index.html`, which blocks direct `iframe.contentWindow.someFunction()`
calls (silently fails — this was the actual bug reported and fixed). The working
approach is `postMessage`, which is exempt from that restriction:

```js
// index.html (parent) — button handlers
document.getElementById('proposalFrame').contentWindow.postMessage({action:'print'}, '*');
document.getElementById('proposalFrame').contentWindow.postMessage({action:'exportWord'}, '*');
document.getElementById('proposalFrame').contentWindow.postMessage({action:'save'}, '*');
```
```js
// مقترح.html — listener
window.addEventListener('message', e => {
  const action = e.data && e.data.action;
  if (action === 'print') window.print();
  else if (action === 'exportWord') _exportWord();
  else if (action === 'save') _saveProposal();
});
```
`مقترح.html` also keeps its own local toolbar for when it's opened standalone (not
inside an iframe); it self-hides via `if (window !== window.top) document.write('<style>#_localToolbar{display:none}</style>')`.

**Print** — plain `window.print()`. The toolbar and the `.tip` hint are hidden in
`@media print`, and `.a4-page` switches to real-page sizing (§4).

**Export Word** — clones `#proposalForm`, manually syncs live DOM *properties* into
*attributes* before serializing (this is required because `outerHTML`/`innerHTML` only
reflect attributes present in markup, not live `.value`/`.checked`/`.selected` state):
```js
form.querySelectorAll('select').forEach(s => [...s.options].forEach(o => o.toggleAttribute('selected', o.selected)));
form.querySelectorAll('input[type="date"]').forEach(i => i.setAttribute('value', i.value));
form.querySelectorAll('input[type="checkbox"],input[type="radio"]').forEach(i => i.toggleAttribute('checked', i.checked));
```
Then wraps the HTML in Word-compatible namespaces and downloads it as `.doc` (the
"HTML-as-.doc" trick Word understands):
```js
const html = `<html xmlns:o="urn:schemas-microsoft-com:office:office" xmlns:w="urn:schemas-microsoft-com:office:word" xmlns="http://www.w3.org/TR/REC-html40">
  <head><meta charset="utf-8"><title>Proposal</title></head><body>${form.innerHTML}</body></html>`;
const blob = new Blob(['﻿', html], { type: 'application/msword' });
// download via a temporary <a download="Proposal_<txNo>.doc">
```

**Save** — see §6. Explicitly **excludes** the uploaded images (GIS photo + 3
signatures) from the DB payload — only boolean flags (`has_gis_image`, `has_eng_sig`,
`has_sec_sig`, `has_mgr_sig`) are stored, not the base64 image data — to avoid bloating
the database with binary blobs.

## 6. Persistence — Supabase

Reuses the same public/anon Supabase project already embedded in `index.html`
(`SUPA_URL` + anon `SUPA_KEY`), duplicated locally inside `مقترح.html` since it's a
standalone file with no shared JS module system.

### Table schema (run once in Supabase SQL editor)

```sql
create table if not exists public.proposals (
  id uuid primary key default gen_random_uuid(),

  ref_no text, project_description text, station text, district text, requesting_department text,
  tx_no text, cap numeric, complaints text,

  v_rn text, v_yn text, v_bn text, v_ry text, v_rb text, v_yb text,
  t_r text, t_y text, t_b text, t_n text, tx_pct text,
  f_r text, f_y text, f_b text, f_n text, f_pct text,

  cable_size text, connection_point text,
  option1 text, option1_cost text, option2 text, option2_cost text,
  reason text, risk text,

  free_spare text, asset_types text[], recommendation text,

  eng_name text, eng_date date, sec_name text, sec_date date, mgr_name text, mgr_date date,

  has_gis_image boolean default false, has_eng_sig boolean default false,
  has_sec_sig boolean default false, has_mgr_sig boolean default false,

  created_at timestamptz default now()
);

alter table public.proposals enable row level security;
create policy "Allow anon insert on proposals" on public.proposals for insert to anon with check (true);
create policy "Allow anon select on proposals" on public.proposals for select to anon using (true);
```

`fNum` / `fSize` / `fAmp` are **not** persisted (no columns for them) — they're derived
fresh from the live readings every time the form opens, like the rest of the reading data.
Add e.g. `f_num text, f_size text` columns and map them in `_saveProposal` if the feeder
number/cable size ever needs to be stored.

### Save (`_saveProposal`)
Maps every camelCase `d` field to the matching snake_case column and `POST`s it to
`/rest/v1/proposals` (standard PostgREST insert, `Prefer: return=minimal`). Shows a
bottom toast (`_toast(msg, isErr)`) on success/failure.

### Load-on-open (`_loadSavedProposal`)
Runs automatically once the form has rendered. Because the **live reading data**
(voltage/current per round) should always come fresh from the app, not from a stale
save, only the **authored/administrative fields** are restored from the last saved row
for the same `tx_no`:
```js
GET /rest/v1/proposals?tx_no=eq.<txNo>&order=created_at.desc&limit=1
```
Restores: `refNo, projDesc, district, reqDept, complaints, cableSize, connPoint, opt1,
opt1Cost, opt2, opt2Cost, reason, risk, freeSpare, assetTypes, recommendation, engName,
engDate, secName, secDate, mgrName, mgrDate`. Explicitly does **not** touch
`vRN..vYB/tR..tN/fR..fN/txPct/fPct` (those stay driven by the selected reading round).
On success, re-renders the form and shows a "📥 Loaded previously saved data" toast.
Fails silently (no toast) if there's no prior save yet, or on network error — this is
expected/normal for a first-time save.

## Porting checklist for the other project

1. Copy `مقترح.html` in full (it's self-contained aside from `nama.png`).
2. Copy `nama.png` (logo, used for both page headers and the small footer-style credit —
   swap for the target project's own logo/branding if different).
3. Copy the `openProposal` / `closeProposalOverlay` functions and the 📝 button +
   `proposalOne` wiring into wherever the equivalent "alerts/report" list lives in the
   other project; adapt the data source (`records`, `getAllRounds`, capacity/rating
   formula) to that project's schema.
4. Update `SUPA_URL`/`SUPA_KEY` in `مقترح.html` (both `_saveProposal` and
   `_loadSavedProposal`) to the target project's Supabase project, or point it at
   whatever backend that project uses instead.
5. Run the `proposals` table SQL (§6) against the target Supabase project.
6. If the other project also risks being opened via `file://`, keep the `postMessage`
   pattern (§5) rather than direct `contentWindow.fn()` calls.
